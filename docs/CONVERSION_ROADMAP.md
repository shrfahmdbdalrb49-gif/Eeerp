# خطة التحويل التدريجي لنظام شرف ERP نحو وثيقة SHARAF_ERP_STRICT_FINAL v4.0

**التاريخ:** 14 أغسطس 2026 | **المؤلف:** Manus AI

## المبدأ الحاكم

يحتفظ النظام الحالي (Vue 3 + Express + PostgreSQL + Demo Mode على GitHub Pages) بوظيفته الكاملة في كل خطوة من خطوات هذه الخطة. لا توجد أي مرحلة تسمح بكسر النظام العامل من أجل ميزة مستقبلية. كل حزمة تحسينات تُنفَّذ، تُختبر فعليًا، وتُنشر، ثم يُبنى عليها التالي. هذه القاعدة تحمي الاستثمار المبني حتى الآن وتمنح كل مرحلة قيمة مستقلة قابلة للاستخدام.

## الحزم التنفيذية (بترتيب الأولوية)

### الحزمة 1 — الأساس المحاسبي الآمن (منفذة جزئيًا)
1. **ترقيم المستندات بمعاملة واحدة:** جدول `document_sequences` + `INSERT ... ON CONFLICT DO UPDATE ... RETURNING` داخل معاملة، بحيث لا يتكرر رقم الفاتورة ولا السند حتى تحت ضغط متزامن، ولا تضيع أرقام عند الفشل.
2. **Soft Delete للمستندات:** حذف منطقي (`deleted_at` + `is_deleted`) للفواتير والسندات والقيود؛ لا يُمسح مستند محاسبي أبدًا فعليًا.
3. **الحد الائتماني للعميل:** عند ترحيل فاتورة آجلة، رفض (أو تحذير بصلاحية تجاوز) إذا تجاوز المبلغ حد العميل الائتماني.

### الحزمة 2 — الانضباط المالي
4. **إقفال الفترات المالية:** جدول `fiscal_periods` مع `is_closed`؛ الترحيل لأي مستند بتاريخ فترة مقفلة ممنوع حتمًا في الخادم.
5. **إلغاء الترحيل (Reverse):** كل مستند مرحّل يُنتج قيدًا عكسيًا وسجلات عكسية بدل التعديل المدمر، كما تنص الوثيقة.
6. **توزيع المدفوعات على الفواتير:** جدول `payment_allocations` يربط كل سند قبض/صرف بالفواتير المسددة فعليًا، ليصبح تقرير أعمار الديون دقيقًا 100%.

### الحزمة 3 — المخزون الاحترافي
7. **طبقات التكلفة FIFO/FEFO مع رصيد متراكم:** حقل `quantity_balance` و`total_cost_balance` في حركات المخزون كما في الوثيقة، مع عرض طبقات التكلفة في شاشة المخزون.
8. **الجرد الدوري:** شاشة `inventory_adjustments` تحسب الرصيد النظامي، يقارنه بالمقاس الفعلي، ويولّد حركة وقيدًا محاسبيًا للفروقات.
9. **منع البيع السالب (إعدادي):** `allow_negative_stock` مع تحقق في الترحيل.

### الحزمة 4 — الصندوق والشيكات
10. **دورة حياة الشيكات:** جدول `cheques` (received/issued × pending/cleared/bounced) مع القيود الخاصة بحساب "شيكات برسم التحصيل".
11. **التحويلات بين الحسابات النقدية:** سند تحويل داخلي بين الصناديق والبنوك.

### الحزمة 5 — الصلاحيات والتدقيق
12. **RBAC حقيقي:** جدول `roles` + `permissions` + `role_permissions`؛ فرض الصلاحية في الخادم (JWT payload يحمل الصلاحيات) وليس إخفاء الأزرار فقط.
13. **Audit Log كامل:** تسجيل CREATE/UPDATE/DELETE/POST/REVERSE مع القيم قبل وبعد وIP والمتصفح.

### الحزمة 6 — التوطين والتقارير
14. **i18n عربي/إنجليزي:** مفاتيح ترجمة JSON + تبديل RTL/LTR (مكتبة i18n في Vue — لا ننتقل لـ React).
15. **التقويم الهجري للعرض:** ميلادي للتخزين (UTC ISO 8601) وهجري للعرض حسب الإعداد.
16. **تصدير CSV/PDF لكل التقارير** + طباعة الفاتورة برأس معلومات الشركة.

### الحزمة 7 — الأداء والبنية
17. فهارس مركبة وفهارس جزئية على الجداول الأضخم (PostgreSQL).
18. تحسين أداء قائمة الأصناف (بحث جزئي + حد نتائج).
19. Code splitting في Vite للتحميل الكسول للشاشات الثقيلة.

### يُؤجَّل حتى وجود عملاء فعليين (لا يُنفَّذ الآن)
- Multi-Tenant SaaS والفوترة والتسجيل الذاتي.
- NestJS / React / TypeORM (إعادة كتابة كاملة).
- Redis وRead Replicas وMicroservices.
- المرحلتان الثانية والثالثة (تصنيع، رواتب، BPMN، Marketplace).

## معايير قبول كل حزمة (غير قابلة للمساومة)
- تُختبر سيناريوهات حقيقية في المتصفح على GitHub Pages وفي الخادم معًا.
- البيانات لا تضيع بعد Refresh، ولا تتغير بنية التخزين المحلي دون ترقية مهاجرة (migration).
- Demo Mode يبقى يعمل بالكامل بعد كل حزمة.
- البناء الأخضر (اختبارات الخادم تمر 100%) قبل النشر.
